## 1. Суть

Мод даёт эндгейм-ступень на Create. Редкие чертежи тиров T1–T5 находят в данжах (очень редко — в обычных сундуках). Каждый чертёж привязан к одному типу предмета: оружие, броня или инструмент.

Игрок вставляет чертёж в скрафченный компьютер-терминал и кладёт стартовый предмет — **сам целевой предмет** (чтобы получить кирку T2, кладут кирку). Терминал показывает только общее число шагов и число операций каждого типа, без порядка, и чего не хватает линии. Игрок собирает линию Create и прогоняет заготовку. Цепочка скрыта от JEI/EMI: это исследование, а не рецепт из справочника.

После каждого прогона терминал пишет процент исследования — долю шагов, угаданных на своих местах. Усиленный предмет выдаётся **только при 100%**. Меньше 100% даёт **хлам**. Предмет и ресурсы деплоеров тратятся в обоих случаях.

Роли: искатель приносит «сырой» оригинал, инженер подбирает последовательность. Знание последовательности — товар. Копия без знания дешевле, копия вместе со знанием дороже.

Тема сервера Ikaria (борьба человека и техники с природой) здесь проявляется так: редкий найденный документ, завод, который нужно собрать руками, и знание, которое нельзя просто скопировать предметом.

## 3. Закрытые решения (канон)

Даты — по карточкам и записям 3–4 ноября 2026. Если не указано иное, это решения Егора.

### 3.1. Находка и предмет чертежа

- Чертежи редкие и тировые. Основной источник — данжи. Очень редко — обычные сундуки. С мобов в MVP не падают.
- Каждый чертёж делает один тип предмета (оружие, броня или инструмент).
- В MVP цели: ванильные меч, кирка, нагрудник; тиры только T1–T3.
- Цвет иконки показывает тир, блёклость — копию. Символ в углу — тип предмета. База — официальная текстура Егора `blueprint_item.png` 16×16, раскладка пикселей не менялась, перекрашена палитра. Иконки уже готовы (карточка `h9cte9I7` в «Готово»).
  - T1 — исходный синий, T2 — индиго, T3 — фиолетовый, T4 — пурпурный, T5 — золотой.
  - Копия — блёклая версия цвета своего тира.
  - Утверждённые типы символа: меч, кирка, топор, лопата, мотыга, шлем, нагрудник, поножи, ботинки.
  - **[предложение]** дополнительные типы: лук, арбалет, трезубец, щит, булава (арт уже есть, в MVP контентом не являются).
- Оригинал в MVP вечный. С 0.2 формулировка меняется: «вечный, пока не перегрет».
- Копию нельзя копировать. **[предложение на макетах, в карточках 0.2 принято как направление: копии печатает оригинал]**.

### 3.2. Терминал и информация

- Скрафченный компьютер-терминал — свой блок. Это не Архив со `main`.
- При вставке чертежа терминал показывает **только** общее число шагов и количество операций каждого типа, без порядка. Пример: «5 шагов: 3 прессования, 2 обжига».
- Терминал также показывает, чего не хватает линии. Сканер линии и вкладка «Линия» в полном виде — не обязательная часть MVP (в карточке терминала `hmZn6lNE` сканер явно «не входит»; в обзоре 0.1 «чего не хватает» фигурирует как цель версии — уточнить в задаче терминала и не делать финальный сканер мира без макета).
- Реализация UI — только после макета. Для MVP допустим простой базовый GUI. За ориентир раскладки можно брать прототип v2, но финальный вид в стиле компьютера Create делается в 1.0 по утверждённому макету.
- Цепочка скрыта от JEI/EMI. Страницы JEI/EMI из PR #7 этому правилу противоречат.

### 3.3. Стартовый предмет и прогон (4 ноября 2026)

- Стартовый предмет — сам целевой предмет. Чтобы получить кирку T2, в терминал кладут кирку. Отдельного «стартового материала из рецепта» нет. **[отменено 4 ноября]** вывод стартового материала из рецепта цели (слитки и таблица запасных значений; на макетах v1 был «Старт: железный слиток ×1» и кнопка «Создать заготовку»).
- Терминал превращает положенный предмет-цель в заготовку. Заготовка помнит чертёж, сид и записывает выполненные операции по порядку.
- Предмет расходуется на **каждой** попытке, и при успехе, и при неудаче.
- В рецепт (цепочку) можно включать ручные активаторы (деплоеры) с ресурсами. Ресурсы тоже тратятся при любой попытке. Чем выше тир, тем больше и дороже ресурсов на попытку. Конкретные числа — открытый баланс; **[предложение]** число деплоеров с ресурсами: T1 0–1, T2 1–2, T3 2–3, T4 3–4, T5 4–6.
- В MVP две операции на линии: механический пресс Create и массовый обжиг вентилятором. Заготовка спокойно проезжает мимо станков, которые её не берут. Рецептов этих операций в JEI/EMI быть не должно.
- **[отменено 4 ноября]** правило «неправильный шаг просто не засчитывается».

### 3.4. Оценка прогона и исследование (4 ноября 2026)

- Сравнение с эталоном — **по позициям**, не LCS: доля шагов, стоящих на своих местах. 5 верных из 10 = 50%. Следующий прогон с 2 верными из 10 = 20%.
- Результат **бинарный**: усиленный предмет только при 100%. Всё, что меньше, даёт хлам.
- **[отменено 4 ноября]** «чем ближе прогон к эталону, тем лучше / сильнее предмет». Качество выше порога больше не масштабирует статы.
- Процент после каждого прогона — только обратная связь для исследования.
- Копиям процент **не передаётся**. Знание остаётся у игрока и само становится товаром.
- Карточка оценки (`n98ZPnvE`) также говорит: процент исследования не хранится в чертеже. Это нужно согласовать с более ранней карточкой предмета (`W30L1ZVn`), где в компонентах указана «изученность %» — см. конфликты и открытые вопросы.

### 3.5. Сид и генерация цепочки

- Сид ленивый: присваивается при генерации в луте, при первом попадании в инвентарь или при вставке в терминал.
- Цепочка — чистая функция от сида, тира и определения чертежа. Свой ГПСЧ (например SplitMix64), версия генератора хранится в компоненте.
- Один сид всегда даёт одну цепочку (это должно быть закрыто эталонными векторами в JUnit).
- Цепочка не должна состоять из одних прессовок. Длина берётся из диапазона тира.
- Чертёж из творческой вкладки получает свою уникальную последовательность, как найденный. Во вкладке он может быть «пустым», без сида, до первого попадания в инвентарь.

### 3.6. Лут (MVP)

- Чертежи T1–T3 кладутся в существующие таблицы лута данжей глобальными модификаторами NeoForge.
- Тир смещается по месту находки, цель выбирается независимо.
- С мобов не падают.
- Шанс умножается на `rarity.multiplier` из конфига.
- Сид присваивается при генерации в луте.
- Структуры Ikaria и лут T4–T5 — не MVP (0.5 / 0.4).

### 3.7. Datapack

- Тиры и цели читаются из datapack JSON. Битый JSON не роняет сервер.
- В тире: диапазон шагов, разрешённые операции, множитель бонуса, цвет, стоимость попытки (пул ресурсов деплоеров и диапазон их числа).
- В цели: предмет, тип для символа. Предмет цели одновременно стартовый, отдельного поля «стартовый материал» нет.
- Полная кастомизация (предметы других модов, свои тиры, синхронизация с клиентом) — 0.3. В 0.1 достаточно минимального пакета T1–T3 и трёх ванильных целей.

### 3.8. Копии и перегрев (0.2, решено по сути, числа открыты)

Решения 3 ноября, уточнение 4 ноября:

- Оригинал печатает копии с ограниченным числом запусков (продать, подарить).
- Каждая копия добавляет оригиналу перегрев.
- На максимуме перегрева оригинал навсегда становится выцветшей копией с ограниченными прогонами.
- Перегрев снимается производством предметов по этому чертежу.
- **[отменено 4 ноября как формула]** «чем ближе прогон к правильной последовательности, тем больше снимает перегрев». Причина: качества прогона больше нет, результат бинарный. Как снимать теперь — открытый вопрос; простейший вариант: снимает только прогон со 100%.
- Копиям процент исследования не передаётся.

### 3.9. T5 и внешний вид (0.4)

- T5 (золотые) дают уникальные предметы со своим скином и уникальными перками.
- Цвет предмета показывает тир и статус копии (копии блёклые).
- Мутации T5 (случайный перк из пула) — отдельная карточка 0.4.

### 3.10. Кастомизация (принцип, с 0.1 схема, полнота в 0.3)

Всё должно настраиваться datapack JSON: предметы в том числе из других модов, новые тиры, диапазон шагов, станки и инструменты, бонусы.

## 4. Что не входит в MVP (0.1)
