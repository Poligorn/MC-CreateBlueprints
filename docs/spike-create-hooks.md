# Спайк: перехват станков Create без рецептов

Карточка Trello `Agmz84v6`, задача 1 из `docs/MVP_TASKS.md`. Ветка `feat/0.1-create-hook-spike` от `main` (`a192e12`).
Create `6.0.10-281`, NeoForge `21.1.252`, Minecraft 1.21.1.

## Ответ

| Станок | Можно узнать об операции и изменить заготовку без рецепта? | Миксин нужен? |
|---|---|---|
| Механический пресс | **Да**, с оговоркой про установку хука (см. ниже) | Нет |
| Массовый обжиг вентилятором (Bulk Blasting, вентилятор за лавой) | **Да** | Нет |

Миксин не добавлялся. Рецепты Create мод не регистрирует.

Под «массовым обжигом» понимается `AllFanProcessingTypes.BLASTING` (в английском Create «Bulk Blasting», подпись «Fan behind Lava»). Это предположение: в задаче станок назван только по-русски. Если имелся в виду вентилятор за огнём (`SMOKING`), схема та же, меняется одна строка делегата.

## Пресс

**API.** `PressingBehaviour.specifics` — публичное, не `final` поле, а `PressingBehaviourSpecifics` — публичный интерфейс. `MechanicalPressBlockEntity#getPressingBehaviour()` публичен. Хук подменяет `specifics` делегирующей обёрткой (`SpikePressHook.Wrapper`):

- `tryProcessOnBelt(input, outputList, simulate)`: если на ленте заготовка (есть компонент метки), при `simulate` возвращает `true` (пресс запускает ход), без `simulate` кладёт в `outputList` копию заготовки с добавленной операцией `press`. Create сам заменяет предмет на ленте результатом.
- Всё остальное (`tryProcessInBasin`, `tryProcessInWorld`, `canProcessInBulk`, `onPressingCompleted`, ...) и любой предмет без метки — прямой вызов оригинала. Обычное прессование слитка в пластину работает (GameTest).

**Установка обёртки — слабое место.** Create не даёт события «блок-сущность пресса создана». Обёртка ставится:

- при `ChunkEvent.Load` на все прессы чанка;
- при `BlockEvent.NeighborNotifyEvent` на изменённую позицию и на уведомляемых соседей.

Проверено: пресс, поставленный обычным `setBlock`, получает обёртку; пресс, поставленный с флагом 2 (без обновления соседей — так ставят структуры и часть команд), обёртку **не** получает, пока рядом не изменится блок или не перезагрузится чанк (GameTest `pressPlacedWithoutNeighbourUpdatesIsNotWrappedYet` фиксирует это поведение). Путь через `ChunkEvent.Load` тестами не прогонялся.

Если для задачи 7 этого мало, запасной вариант — один миксин `@Inject` в начало `MechanicalPressBlockEntity#tryProcessOnBelt` в пакете `compat.create`. Он не требует установки, но привязывает мод к имени внутреннего метода. Здесь он не писался.

## Массовый обжиг вентилятором

**API.** `CreateRegistries.FAN_PROCESSING_TYPE` — публичный реестр NeoForge, `FanProcessingType` — публичный интерфейс. Мод регистрирует тип `blueprintforge:spike_blasting` (`SpikeFanBlastingType`):

- `isValidAt` делегирует `AllFanProcessingTypes.BLASTING`: тип действует ровно там, где действует обычный обжиг (вентилятор за лавой);
- `getPriority` = приоритет обжига + 1, поэтому `FanProcessingType.getAt` возвращает наш тип;
- `canProcess` / `process`: для заготовки — `true` и копия с операцией `blast`; для остальных предметов — делегат в `BLASTING`. Обычный обжиг сырого железа в слиток работает (GameTest);
- частицы, воздушный поток и действие на сущности — делегат.

Вентилятор за водой (`SPLASHING`) и за костром (`SMOKING`) по-прежнему выбираются Create как свои типы, заготовку они не трогают (GameTest проверяет и выбор типа, и то, что журнал остался пустым).

**Время обработки.** Массовая обработка идёт не мгновенно: в тесте у предмета в потоке `processingTime` отсчитывался от значения порядка 150 тиков (число из конфига Create не читалось). Предмет, проехавший поток быстрее, не обработается: по грубой оценке лента 16 об/мин проходит блок за десятки тиков (замер не делался). Для генератора линий и для сцен тестов это значит: вентилятору нужен длинный поток или медленная лента. Тесты используют остановленную ленту или 1 об/мин.

## Метка и журнал

Спайк использует временный компонент `blueprintforge:spike_line` (список строк-операций). Это не дизайн заготовки: настоящий компонент заготовки — задача 7. Компонент и тип вентилятора нужно заменить или убрать в задаче 7, иначе предметы с `spike_line` в сохранениях останутся без владельца.

Журнал записывает то, что реально сработало, в порядке срабатывания. Сверка с цепочкой — не задача спайка.

## Что делает «не тот» станок

- Предмет без метки: пресс и вентилятор ведут себя как обычно.
- Заготовка под вентилятором за водой или костром: не меняется, не расходуется (GameTest).
- Заготовка под выключенным прессом: не меняется, не расходуется (GameTest).
- Заготовка под станком Create, которого мы не трогаем (деплоер, пила и т. д.): не проверялось; они не подключены к нашим хукам, поэтому не должны записывать шаг.

## Находка про сборку

На момент спайка в пакете `com.blueprintforge.compat.create` все классы принадлежали миксин-конфигу прототипа Архива, и любой обычный класс там ронял загрузку (`IllegalClassLoadError ... is in a defined mixin package`). Поэтому хуки лежат в `com.blueprintforge.compat.createapi`. Прототип Архива и его миксины потом убраны, но пакет остался как есть: миксинов в моде сейчас нет.

Второе наблюдение: однажды `./gradlew runGameTestServer` завершился `BUILD SUCCESSFUL`, хотя в логе был `Mod loading has failed` (как раз из-за этой ошибки). Провал отдельного теста даёт код 1, а падение загрузки мода — не обязательно. Для вывода «зелёное» нужна строка `All N required tests passed` в логе.

## Что не проверялось

- Клиент (`runClient`): синхронизация компонента на клиент, отображение предмета. Ни один клиентский код не запускался.
- JEI и EMI в dev-среде не стоят. Что хук не добавляет страниц просмотрщика, следует из того, что мод не регистрирует ни тип рецепта, ни сериализатор, и из теста на отсутствие рецептов. Сам просмотрщик не запускался. Предположение, что тип вентилятора из реестра сам по себе не создаёт категорию JEI, не проверено.
- Установка обёртки при загрузке чанка (`ChunkEvent.Load`) и после перезапуска сервера. Сохранение и загрузка предмета с компонентом.
- Прессование на механизме (contraption), в тазу (basin) и предметом-сущностью под прессом: хук для них делегирует оригиналу, заготовку там не штампует.
- Обжиг заготовки, лежащей на земле (`ItemEntity`): путь идёт через тот же `FanProcessingType`, но не тестировался.
- Заготовка в стопке больше одного предмета; заготовка, вернувшаяся на тот же станок по замкнутой ленте.
- Другие станки Create над лентой (деплоер, пила, наполнитель), аддоны Create и другие моды, подменяющие `specifics` пресса.
- Другие версии Create, кроме `6.0.10-281`. Поле `specifics` публично, но это не документированный контракт.
- Игровой процесс на выделенном сервере вне GameTest (`runServer`).
