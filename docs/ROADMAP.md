## Чеклист приёмки MVP 0.1

> **Состояние на 27 ноября 2026.** Задачи 1–10 лежат на `main` (PR #19 — последняя), задачи 11 (лут) и 12 (сведение) делаются в ветке `feat/0.1-loot-and-mvp`. Статус каждого пункта чеклиста ниже, с оговорками и тем, что не проверялось в игре, — в [MVP_0.1_STATUS.md](MVP_0.1_STATUS.md). Терминал v3 (PR #18) в эту сводку не входит.


Версия 0.1 готова, когда всё ниже верно в игре (не только «в коде»):

- [ ] Спайк записан: пресс и массовый обжиг можно отследить и изменить заготовку без зарегистрированного рецепта; указан API или обоснованный миксин.
- [ ] Тиры T1–T3 и цели (меч, кирка, нагрудник) загружаются из datapack. Битый JSON не роняет сервер. В тире задана стоимость попытки.
- [ ] Предмет-оригинал T1–T3 есть в игре с официальными иконками (цвет = тир, символ = тип). Тултип показывает название и тир.
- [ ] Один сид всегда даёт одну цепочку (JUnit с эталонными векторами). Цепочка не из одних прессовок, длина из диапазона тира. Сид выдаётся лениво.
- [ ] Из творческой вкладки можно взять все типы × T1–T3; при выдаче генерируется своя последовательность.
- [ ] Терминал принимает чертёж и предмет-цель, показывает число шагов и операции по типам **без порядка**, выдаёт заготовку.
- [ ] Заготовка проходит линию из пресса и вентилятора (обжиг); операции пишутся в прогон по порядку; в JEI/EMI этих рецептов нет.
- [ ] Деплоеры с ресурсами из JSON тира списывают предметы на попытку; у T3 попытка заметно дороже, чем у T1.
- [ ] После каждого прогона терминал пишет процент по позициям. При 100% выдаётся усиленный меч, кирка или нагрудник. При меньшем проценте — хлам. Предмет-цель и ресурсы деплоеров тратятся в обоих случаях.
- [ ] Чертежи T1–T3 иногда находятся в сундуках данжей, сид выдаётся при генерации лута, с мобов не падают.
- [ ] `./gradlew test`, `./gradlew build` и `./gradlew runGameTestServer` проходят. В PR написано, что ещё не гонялось руками.
- [ ] Нет копий, перегрева, T4–T5 и финального GUI. Нет страниц JEI, раскрывающих цепочку.
